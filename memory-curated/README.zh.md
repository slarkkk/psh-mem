# @deepseek-ai/dsh-memory-curated

[English](README.md) | 中文

## 概述

记忆能力随包提供的提供方。它拥有 `memory` 与 `user` 两个目标，把每个目标作为有界条目列表持久化在一个存储域中，并把它们渲染为一个系统提示词段落。它的写入路径就是该能力定义的批处理语义：一次调用中的每个操作都针对目标的最终字符预算应用，否则一个都不应用。提示词段落每个会话只捕获一次，因此条目保持可见，而不会移动会话已经发送过的提示词前缀。

<a id="storage"></a>
## 存储

条目存放在名为 `memory` 的一个存储域中，通过 `ctx.storageDomain` 打开，并由插件自身的 effect 释放函数关闭。该域为每个目标持有一条记录，因此部署能获得它为该域所路由到的存储后端的持久性、schema 校验与单写入者保证——默认是 `$DSH_HOME/storages` 下的 JSON 后端。

条目以列表形式存储，字符预算是按用条目分隔符连接后的该列表度量的，因此分隔符也计入目标上限所约束的预算。

<a id="write-semantics"></a>
## 写入语义

一次调用携带一个操作列表，字符预算按**整个列表的最终结果**检查，绝不按操作逐个检查。正因如此，当单看添加本身已经溢出时，一次调用仍可以同时移除或缩短陈旧条目并添加新条目。

操作是全有或全无的：失败会让已存条目完全保持原样，并返回当前快照，因此调用方能看到在重试前需要整合什么。`replace` 和 `remove` 通过条目文本的子串定位该条目；匹配多个*不同*条目的子串会因歧义被拒绝，而不是按位置消解。完全重复的 `add` 会成功，且不会存下第二份副本。

成功的写入报告用量和一条完成提示，绝不回显条目列表，因为回显的列表会诱使模型去找更多要修的东西，并重复它已经做过的工作。

失败的写入绝不把轮次扣作人质。在一个轮次内达到配置的失败整合尝试次数之后，该轮次中后续的失败会变成终止性的：它们的消息告诉调用方停止重试、让记忆保持不变并继续回复。成功的写入会重置计数，而计数在每个轮次边界重置。

<a id="the-frozen-section"></a>
## 冻结的段落

提供方注册一个系统提示词段落，其文本在某个 scope 首次组装时渲染，随后对该 scope 剩余的每次组装都逐字复用。因此，会话进行中做出的写入不会移动该会话已经发送过的提示词前缀；模型从工具结果里读回自己的写入，并在后续会话中从该段落里读回它。

该段落在自己的前导中说明了这一点，因此刚写入一个条目的模型不会把未变的文本读成写入失败。没有任何条目的目标不贡献块，而两个目标都为空的部署完全不带该段落——组装会丢弃空段落。

<a id="configuration"></a>
## 配置

| 字段 | 默认值 | 作用 |
|---|---|---|
| `memoryLimit` | `2200` | `memory` 目标的字符预算，按其连接后的条目度量。 |
| `userLimit` | `1375` | `user` 目标的字符预算，按其连接后的条目度量。 |
| `consolidationFailureLimit` | `3` | 在一个轮次内，某个目标的 `over-budget` 与 `no-match` 写入失败达到多少次后，该目标的写入在该轮次内变为终止性。 |
| `providerName` | `curated` | 该提供方在 `ctx.memory` 上注册所用的名称。 |

生成的[配置目录](../../../docs/config-catalog.zh.md#deepseek-aidsh-memory-curated)是每个受支持字段及其 JSDoc 的穷尽来源。

<a id="model-experience"></a>
## 模型体验

### 策展记忆的系统提示词段落

#### 模型看到什么

一个提示词段落，仅当至少一个目标存有条目时出现。它以一段前导开头，说明这些条目是什么以及该快照对当前会话冻结，然后为每个非空目标携带一个块，块头是目标名称及其用量。

##### 逐字的前导段落

```markdown
Curated memory: durable entries that outlive this session. This snapshot is frozen for the current session, so an entry written now appears here only in a later session.
```

##### 逐字的目标块形态

```markdown
## <target> (<pct>% — <chars>/<limit> chars)
<entry>
§
<entry>
```

#### Token 影响

保留。该段落是会话每个轮次请求前缀的一部分，其大小由它携带的条目决定，并以两个目标上限加上前导与块头为界。两个目标都没有条目时为零。

#### KV Cache 影响

按构造在会话内前缀稳定：文本在 scope 首次组装时捕获，之后永不重新渲染，因此同一会话稍后做出的写入无法使该前缀失效。新会话会渲染一份新快照，它可能与上一个会话的不同。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与延期工作

- **记忆是机器作用域，不是项目作用域**——两个目标由该部署服务的每个会话共享，因此在一个项目中了解到的事实会在另一个项目中被提供。想要隔离的部署应配置一个单独的存储域，而不是过滤条目。
- **会话无法从提示词中读回自己的写入**——冻结正是保持前缀稳定的原因；工具结果是唯一的会话内确认。段落前导向模型说明了这一点，但只读提示词的调用方仍可能感到意外。
- **没有合并或取代操作**——条目可以通过子串匹配被替换或被移除，但没有任何东西会自动合并两个重叠的条目，因此保持存储自洽是调用方的工作。
- **条目没有来源信息**——条目只记录自己的文本，不记录哪个会话或轮次写入了它们，因此读者无法判断某个条目是何时、为何被添加的。

<a id="dev-note"></a>
### 开发备注

<details>
<summary>维护者的工作上下文——点击展开</summary>

不发布不变式配套插件，因为存储在构建自身结果的过程中校验了每种关系：被拒绝的写入返回它未改动的条目，成功则返回该写入所产生的状态。冻结是 scope 与捕获时存储状态的纯函数，因此外部观察者重新计算的正是它被调用时所处的那次调用。

整合失败计数器是按轮次、按存储计，而不是按目标计。它的存在是为了阻止重试循环耗尽一个轮次的预算；它统计的失败属于调用方而非目标，因此跨目标只计一次才是诚实的作用域。

</details>
