# @deepseek-ai/dsh-tool-memory

[English](README.md) | 中文

## 概述

记忆能力的模型侧消费方。它恰好注册一个工具 `memory`，其唯一的 `operations` 数组携带对一个目标的全部变更。所有面向模型的指引都位于工具描述中：什么属于记忆、为什么一次调用携带全部变更，以及当批次因超出目标预算而被拒绝时该做什么。该工具只通过 `ctx.memory` 读写，因此在任何已注册的提供方之上都无需改动即可工作。

<a id="the-tool"></a>
## 工具

生成的[工具目录](../../../docs/tool-catalog.zh.md#deepseek-aidsh-tool-memory)是受支持参数与规范输出 schema 的穷尽来源。概略地说，一次调用指定一个 `target`（`memory` 或 `user`）和一个 `operations` 数组，其条目为 `add`、`replace` 或 `remove`；`replace` 和 `remove` 通过条目文本中一段简短且唯一的子串来标识该条目。

该工具把整个数组委派给 `ctx.memory.write(target, operations)`，并返回已结算的结局。它不施加自己的策略：预算、匹配规则与全有或全无行为都属于拥有该目标的提供方，因此替换提供方的部署会改变该工具的行为，而不会改变模型收到的说明。

<a id="why-one-batch-shape"></a>
## 为什么只有一种批处理形态

没有单独的单操作形式。一次变更就是只含一项的批次，描述中也如此说明。为同一种意图提供两种形态会让 schema 翻倍，并让模型可以用两条路径到达同一状态，而这正是本仓库要求解释或消除的那类不对称。

<a id="result-rendering"></a>
## 结果渲染

`output.render` 把规范值转成一个文本块。成功会报告提供方的确认与目标的用量。拒绝会报告失败消息，并在提供方返回了它时附上当前条目，因为那正是模型在重试前决定要整合什么所需要的。

渲染是纯的，且只读取规范值，因此被记录的调用会重放为相同内容，而无需重新运行提供方。

<a id="model-experience"></a>
## 模型体验

### `memory` 工具 schema

#### 模型看到什么

工具名称、描述与参数 schema，位于生成的[工具目录](../../../docs/tool-catalog.zh.md#deepseek-aidsh-tool-memory)中。描述是该工具唯一的指引：本插件不注册系统提示词段落，因此该保存什么、为什么一次调用携带全部变更、哪个目标存放什么，以及该跳过什么，全都存在于该文本中。

#### Token 影响

工具可见期间每次请求固定：描述与 schema 在每个轮次都占用提示词 token。注册表拥有确切的 envelope。一次调用的结果是一条简短确认，或是失败消息加目标的条目，而条目列表只在可重试的拒绝中出现。

#### KV Cache 影响

与策展段落的稳定性无关：工具 schema 属于同一个提示词前缀，因此只有当工具集本身变化时才会使其复用失效，而工具集变化发生在组合时，而不是轮次进行中。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与延期工作

- **没有只读检查操作**——模型只能变更。它从拒绝中读出当前条目，并通过提示词段落看到常驻条目，但无法直接请求某个目标的条目。想在变更前审阅记忆的模型没有这样的调用。
- **没有条目级身份**——条目通过其自身文本的子串来寻址，因此只掌握该短语的调用方无法区分两个共享同一独特短语的条目。提供方会把它解析为 `ambiguous-match`，而不是靠猜测。
- **每次调用一个目标**——一个批次恰好寻址一个目标，因此必须把某个事实从 `memory` 移到 `user` 的变更需要两次调用，且在这两次调用之间不是原子的。

<a id="dev-note"></a>
### 开发备注

<details>
<summary>维护者的工作上下文——点击展开</summary>

不发布不变式配套插件，因为该工具不持有状态：每次调用都委派给 `ctx.memory` 并返回提供方结算的结果，而渲染是该值的纯投影。观察该工具的不变式只会在读第二遍提供方的结果。

该工具有意不注册系统提示词段落。`todo_write` 树立了同样的先例：属于单个工具的指引写在它的描述里更好，因为它随 schema 一起传递，而不是留在一段可能与 schema 漂移的独立提示词中。

</details>
